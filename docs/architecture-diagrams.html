Publishing Sequence (Scheduled)

sequenceDiagram
    actor U as User
    participant UI as UI (React)
    participant API as API (Go)
    participant DB as SQLite
    participant SCH as Scheduler
    participant LI as LinkedIn API

    Note over U,LI: Scheduled publishing
    U->>UI: Sets post + date/time
    UI->>API: POST /api/schedule
    API->>DB: writes scheduled_post (status=pending)
    API-->>UI: 201 Created

    loop every tick
        SCH->>DB: fetches due posts (pending)
        DB-->>SCH: due post(s)
        SCH->>DB: reads + decrypts OAuth token
        alt token expired
            SCH->>LI: refresh token
            LI-->>SCH: new access token
            SCH->>DB: writes updated token
        end
        SCH->>LI: POST /ugcPosts (w_member_social)
        LI-->>SCH: 201 + post URN
        SCH->>DB: status=published, saves URN
    end

The scheduler periodically checks for due posts, refreshes the token if needed, and publishes via the official API, recording the result.

Data Model (SQLite)

    DRAFTS ||--o{ DRAFT_VERSIONS : "has"
    DRAFTS ||--o| SCHEDULED_POSTS : "can generate"

        int id PK
        string title
        string source_description
        string content
        string status
        datetime created_at
        datetime updated_at
    }
    DRAFT_VERSIONS {
        int id PK
        int draft_id FK

        datetime created_at
    }
    SCHEDULED_POSTS {
        int id PK
        int draft_id FK
        string content
        datetime scheduled_for

        string linkedin_urn
        string error
        datetime created_at
    }
    OAUTH_TOKENS {
        int id PK
        string provider
        blob access_token_enc
        blob refresh_token_enc
        datetime expires_at
        datetime updated_at
    }
    SETTINGS {
        string key PK
        string value
    }

A minimal schema for drafts with versioning, schedules, encrypted tokens, and settings.
